# Launch runbook

Order matters. Steps marked **you** need a dashboard login; the rest is automated by this repo.

## 1. Database and API on Render (you)
1. Render → New → Blueprint → select `malcryptt/zexcore`. Approve `zexcore-api` and `zexcore-db` (Frankfurt, starter).
2. The first deploy will fail to boot until `DATABASE_URL` exists. That is intended: production refuses to run as the schema owner.
3. From any machine with `psql`, using the database's **External** connection string as `PRIMARY_URL`:
   `PRIMARY_URL='...' APP_PASSWORD='<24+ char password>' ./scripts/db-init-production.sh`
4. On the `zexcore-api` service set `DATABASE_URL` = `postgres://zexcore_app:<APP_PASSWORD>@<internal host>/zexcore_db` (use the **Internal** host), then redeploy.
5. Check `https://<api-url>/api/health`.

## 2. Settings on the API service (you)
| Variable | Value |
|---|---|
| `GOOGLE_CLIENT_ID` | OAuth Web client ID from Google Cloud → APIs & Services → Credentials. Add `https://zexcore.com.ng` and the web.app URL as authorised JavaScript origins. |
| `RESEND_API_KEY`, `EMAIL_FROM` | Resend API key and an address on a domain verified in Resend. Required for password reset and email verification. |
| `PAYSTACK_SECRET_KEY`, `PAYSTACK_PUBLIC_KEY` | Live keys. Webhook URL: `https://<api-url>/api/webhooks/billing/paystack` |
| `PUBLIC_APP_URL` | The public dashboard URL (links in emails). |
| `JWT_SECRET` | Generated by the blueprint. Never reuse the development value. |

## 3. Dashboard on Firebase Hosting
GitHub → Settings → Secrets and variables → Actions:
- Secret `FIREBASE_SERVICE_ACCOUNT`: Firebase console → Project settings → Service accounts → Generate new private key. Use a service account that only has **Firebase Hosting Admin**.
- Variable `VITE_API_URL`: the API's public https URL.
Every merge to `main` then deploys. First deploy can be started from Actions → "Deploy dashboard to Firebase Hosting" → Run workflow.

## 4. Before opening to customers
- Branch protection on `main` (require the CI check, no force pushes).
- Rotate any token that was pasted into chat or logs.
- Enable Render database backups and a paid plan that retains them.
- Send a real password reset and verification email end to end.

## No payment card? Free-tier path
1. Create a Postgres database on Neon (neon.tech, free, no card). Copy the **non-pooled** connection string (the "Direct" one).
2. Render → New → Blueprint → repo `malcryptt/Zexcore`, branch `review/security-fixes-2026-10-24` (or `main` once merged), **Blueprint Path** `render.free.yaml`. This creates only the API on the free plan.
3. Run `PRIMARY_URL='<neon direct url>' APP_PASSWORD='<24+ chars>' ./scripts/db-init-production.sh`.
4. On the API service set `ADMIN_DATABASE_URL` = the Neon direct URL, and `DATABASE_URL` = the same URL but with user `zexcore_app` and your `APP_PASSWORD`. Redeploy.
Limits: free web services sleep when idle, and Neon's free database also pauses when idle (first query is slower). Fine for testing; upgrade both before real customer traffic.
